# Spec: v1.3 Connectors and planning (Track B)

Decisions: D263 (v1.3 part), D264, D267, D268. ADR 0007. Depends on v1.2.

## Goal

Momentum works with the tools people already use, without a server: AI agents, other calendars, and the apps people are switching from. It also gains the planning features users ask for most: a deadline separate from the planned date, durations, Someday, Waiting for and One thing. Every new task field ships on desktop and phone together (D257).

## Out of scope

- Anything that needs a server: bots, the webhook, sent tasks (all v1.4).
- Two-way Google or Outlook sync (it needs Google's review, D259).
- Supabase migrations. Track B adds only local SQLite migrations, in `src-tauri/migrations/` and regenerated for the phone with `node scripts/mobile-migrations.mjs`. Synced-table triggers are regenerated with `node scripts/sync-triggers.mjs`. The matching server columns are listed in a hand-off note for Track C, which adds them in its first migration.

## Task model (Track B owns `Task`)

Use the GLOSSARY terms. "Due" never appears in the UI.
- **Planned date:** `Schedule` gains `{ kind: "someday" }`. A Someday task never appears in Today, Upcoming, the calendar or the Matrix, and it lives in a new Someday smart list.
- **Deadline:** `deadline: LocalDate | null`.
  - Today shows tasks planned for today plus tasks whose deadline is today or past.
  - `src/domain/matrix.ts` takes urgency from the deadline when there is one, otherwise from the planned date.
  - Rows show a deadline chip ("by Fri"), red once it's passed.
- **Duration:** `durationMin: number | null`.
  - It can be set without a time. A timed task's duration is its end minus its start.
  - Today's header shows the day's total ("4h 10m planned").
- **Waiting for:** `waiting: null | { kind: "person"; who: string; followUp: LocalDate } | { kind: "task"; taskId: string }`.
  - A waiting task leaves Today and Upcoming and sits in a Waiting smart list.
  - It comes back on its follow-up date, or when the task it waits on is completed.
  - Waiting on itself or in a loop is refused at the boundary.
- **Quick-add tokens** (`src/domain/quickAdd.ts`, with tests):
  - a deadline: `by fri`, `by 12/3`;
  - a duration: `30m`, `1h30m`, `~2h`;
  - `someday`;
  - `waiting @sam fri` (person and follow-up).
  - Every new token gets a help entry in `FEATURES`.
- **Tag inheritance:** a subtask created under a tagged parent starts with the parent's tags. This happens on creation only; later edits don't flow down.

## Planning features

- **One thing.** A toggle on Today (desktop and phone) shows a single task.
  - The task is chosen by Matrix quadrant, then deadline, then your sort order.
  - Buttons: **Done** and **Not now**, which moves the task to tomorrow.
  - An energy switch, Low or Normal, limits Low to tasks of 15 minutes or less. Tasks without a duration count as Normal.
  - No counts or streaks.
- **End of day:** a setting, Day ends at (00:00–05:00, default 00:00), shifts what Today, overdue and habit days count as "today". The logic lives in `src/domain/dates.ts`, with tests at the boundaries.
- **Focus sessions on the calendar:** a setting (off by default) draws past focus sessions as faint blocks.
- **Snooze to a chosen time** from any task row's menu, using the same picker as reminders.
- **Markdown tables** render in notes (GFM tables in the existing renderer, still with no raw HTML).
- **Habits:** `count` and `amount` goals gain `period: "day" | "week"`. A weekly goal shows progress against the week's total. Quit and limit goals already exist.

## Connectors (desktop)

- **CLI and MCP** (ADR 0007).
  - A localhost-only API in the main window: list, search, get, add (through quick-add), update, complete, and list habits. It runs the same store actions as the UI.
  - A `momentum` binary is shipped alongside the app and put on PATH by an opt-in Settings switch. It has `--json` on every command, and if the app isn't running it starts it in the tray.
  - `momentum mcp` serves the same operations as MCP tools over stdio.
  - Settings → Connections → AI agents shows copy-paste setup for Claude Code, Claude Desktop, Cursor, Codex and Gemini CLI. This is a separate component that Track C mounts (D258).
- **Calendar subscriptions.**
  - Add any `.ics` address (Google's private address, Outlook's published calendar, iCloud, Proton, Fastmail).
  - It refreshes every 30 minutes while the app is open, plus on demand. Events are read-only, in their own colour, and parsed by the existing `src/domain/ics.ts`.
  - Subscribed events sync to the phone as read-only events.
  - It's a Settings panel component for Track C to mount.
- **Import from Todoist and TickTick** from their export files (Todoist CSV/JSON backup, TickTick CSV).
  - Lists, sections, tasks, subtasks, priorities, dates, recurrence where it maps, and tags all come across.
  - A preview with counts comes first, then one undoable import.
  - The parsers live in `src/domain/` with fixture tests.

## Privacy promise (D268)

- Settings → About and the README state it: no telemetry, no clipboard reading, a full export, works without an account, and AI comes through your own agent.
- Check that each claim holds (for example, grep for clipboard reads) before writing it.

## Verification

- Domain tests for every new field, token, the Matrix urgency change, the end-of-day boundaries, Waiting for coming back, weekly habit periods and both import parsers.
- Sync simulation: the new fields round-trip between desktop and phone, and an old phone build doesn't drop them (D257 test).
- Real-app check:
  - Claude Code adds "call mom by fri 15m" through the CLI and it appears in the app;
  - a Google private calendar address shows events;
  - a Todoist export imports;
  - One thing on Low shows only short tasks.

## Acceptance

- An agent can list, add and complete tasks in a running or closed app with one setup step.
- No new task field is lost by syncing through the phone.
- Every new command, token and feature has a `FEATURES` entry.
