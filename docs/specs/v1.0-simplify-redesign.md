# Spec: v1.0.0 Simplify and redesign

Phase A. Decisions: D111–D114, D163–D173, D175–D180, D182. No server work. This release stays fully offline.

## Goal

Answer "it's too much and looks vibecoded". There are fewer places to go, one obvious way to learn the app, and a calm, deliberate visual design that already has room for accounts and friends. No feature that users rely on is lost. Each removal migrates its data or maps to a new place.

## Out of scope

- Accounts, sync and social (v1.1+). They appear only as empty places in the design.
- New task features.

## 1. Navigation and pages

Today's navigation has 4 smart lists and 6 modules (`src/features/shell/nav.ts`).

| Today | v1.0 |
|---|---|
| Inbox, Today, Upcoming | unchanged |
| Logbook (`SMART_LISTS`, `G L`) | removed. A **Show completed** toggle on every task view. The search keyword `done` (which already exists in `domain/filter.ts` `KEYWORDS`) finds completed tasks. This replaces D165's `is:done`, because the keyword already exists. |
| Calendar | unchanged; it also shows countdowns |
| Matrix page | removed. Matrix becomes a **view mode** |
| Habits, Focus | unchanged |
| Countdown page | removed. Countdowns migrate into the calendar (§3) |
| Statistics | renamed and rebuilt as **Progress** (§5) |
| Settings | reorganised (§7) |

- **Go keys:** `G M` switches the current view to Matrix mode. `G D` and `G L` are removed, and `G S` opens Progress. The `SHORTCUTS` table (`Dialogs.tsx:50`) is replaced by the registry (§6).
- **Old ids in saved settings** are mapped by extending `RENAMED_VIEWS` in `domain/settings.ts`: `logbook` → `today` with Show completed, `countdown` → `calendar`, `matrix` → `today` in Matrix mode, `stats` → `progress`.

## 2. Layouts (D114)

- **Key:** `layout` becomes `"sidebar" | "bar"`, plus a new key `barPosition: "top" | "bottom"`.
- **Migrating the old value** (`types.ts:159`): `classic` and `flat` become `sidebar`, `topbar` becomes `bar` at the top, and `dock` becomes `bar` at the bottom.
- **Keys removed:** `dockLabels`. Labels are always shown in the bar, and an overflow "More" keeps D77's grouping. `sidebarSide`, `sidebarCollapsed` and `sidebarMoreOpen` stay.
- **Code:** `App.tsx:40-105` collapses to two branches. `NavBar` gets one variant with a `position` prop. The flat styling of `Sidebar` goes.
- **`LayoutPicker`** shows 3 choices (Sidebar, Bar top, Bar bottom), in Settings → Appearance and in the tour.
- **Narrow windows** (below the one breakpoint, D172) always use the bar at the bottom, which is how a phone will look.

## 3. Countdowns become calendar items (D163)

- **Migration `0008_countdowns_to_events.sql`:**
  - `calendar_events` gets `countdown TEXT CHECK (countdown IN ('until','since'))`, nullable, and `pinned INTEGER NOT NULL DEFAULT 0`.
  - Each `countdowns` row becomes an all-day event:
    - `start_date` = `date`, `span_days` = 1;
    - `countdown` = `direction`, `pinned` = `pinned`;
    - `rrule` = `FREQ=MONTHLY` or `FREQ=YEARLY` when repeat isn't `none`.
  - Then the `countdowns` table is dropped.
  - The icon and colour carry over (`color`; the icon key goes into the title prefix only when it isn't the default, `hourglass`).
- **Backup format:** `backupFormat.ts` still *imports* old `countdowns` arrays (converted the same way) and stops exporting them.
- **EventDialog** gets a "Show countdown" control (Off, Until, Since) and a Pin toggle.
- **Pinned countdowns** show as small chips at the top of Today ("12 days until Trip"). The days come from the existing `domain/countdown.ts` maths, which stays and is pointed at events.
- **Deleted:** `stores/countdowns.ts`, `features/countdown/`, the countdown functions in `db/miscRows.ts`, and the tour's countdown step.
- **Tests:** `countdown.test.ts` keeps its maths cases. A new migration test converts each direction and repeat combination.

## 4. View modes (D164)

- **The view-mode switch** replaces the per-list layout radiogroup (`TaskView.tsx:77`) and appears on **every** task view: List, Board, Matrix, Timeline.
- **Board needs sections,** so it's offered only on real lists, Inbox included. Smart views show List, Matrix and Timeline. This refines D164, because a smart view has no sections to make columns from.
- **Where the mode is stored:**
  - Real lists keep `TaskList.layout`, whose type gains `matrix`.
  - Smart views store their mode in `settings.viewOptions[view].mode`.
- **`MatrixView`** takes the view's task set instead of `useDerived().roots`, keeping only root tasks per D58. Drop and multi-select logic (`MatrixView.tsx:22-37`) is unchanged.
- **Rules:** `RulesEditor` moves into the Matrix mode's header menu.
- **The mini window's Matrix tab** stays global. It keeps reading `snap.matrix` from `domain/mini.ts`.

## 5. Progress (D166, D182)

The new `features/progress/ProgressView.tsx` replaces `StatsView`. Sections, top to bottom:

1. **This week:** tasks done, focus hours and perfect days this week. This is where the weekly score card goes in v1.2. In v1.0 the numbers are local.
2. **Streaks:** the perfect-day streak and rest day (from `TodayStreak`), plus the best streak.
3. **Trophies:** `TrophyShelf`.
4. **Trends:** the 14-day and 12-week bars, the activity heatmap, and habit consistency.
5. **Friends:** an empty state reading "Sign in to add friends and compare your week", with a disabled button until v1.1 or v1.2 enables it.

- **Cut:** "Best day of the week", the "Open tasks by priority" donut and "Where your work went". They're low-signal and add to the "too much" feeling.
- **Share:** a button in the header (`ShareDialog`, unchanged).
- **Today** keeps the compact `TodayStreak` flame.

## 6. Feature registry: Help, Getting started and the tour (D167–D169, D176–D179)

- **New pure module `src/domain/features.ts`,** with tests. Each entry has:
  - `id`, `title`, `howTo` (one line), `icon` (an `AppIcon` key, not a component, so the module stays pure);
  - `since` (the version);
  - `requires?` (`'signedIn' | 'ai'`);
  - `core: boolean`, which marks the 6 core Getting started items;
  - `commands`: palette command ids, shortcut keys and quick-add tokens, each with a description;
  - `done` (an event key). It's ticked when that event fires: `task:created-quickadd`, `task:token-used`, `view:matrix`, `habit:checked`, `focus:completed`, `palette:opened`.
- **The command palette** (`CommandPalette.tsx:55-75`) and the `?` shortcut sheet build their rows from the registry, alongside the existing dynamic sources (lists, tags, tasks, `addPaletteSource`).
- **A test fails** if a palette command or a `GO` key in `lib/shortcuts.ts` has no registry entry.
- **Quick-add tokens get one list in the registry,** and the four hand-written rows go.
- **Help** is a new section in Settings: a search box over the registry, grouped Tasks, Views, Habits & focus, Capture, Progress and Keyboard.
- **Getting started:**
  - A dismissable card at the top of Today with the 6 core items and a collapsible **More to try** section (every other entry the user meets the `requires` for, including voice, the mini window, bulk import, `.ics` import, the Share card, Board and Timeline, habit goals and countdowns).
  - Progress is stored in `settings.gettingStarted {dismissed, done: string[], seenVersion}`, which is per user and syncs in v1.1.
  - After an update, entries whose `since` is newer than `seenVersion` show at the top as "New:", next to What's new.
  - Dismissing hides the card. Help → "Show Getting started" brings it back.
  - AI entries stay hidden until AI exists. Then one entry, "Turn on AI features", is the opt-in (D179).
- **The tour** goes from 15 steps (`Tour.tsx:73`) to 4:
  1. Quick-add and tokens.
  2. Views and Matrix mode.
  3. Habits and focus.
  4. Progress, then the command palette and Help.
- **The tour is for new installs only** (`settings.onboarded`). Upgraders get What's new. The layout picker moves out of the tour into Settings.

## 9. Visual redesign (D113, D172, D173)

- **Process:**
  1. Write the visual brief (below) in `docs/design/brief.md`.
  2. Mock Today, a list (all 4 modes), Progress (including the empty Friends state), Settings → Help and the Getting started card in Claude Design, in light and dark, at desktop and narrow widths.
  3. You approve the mocks.
  4. Then implementation starts.
- **The brief:**
  - References: Things 3 (calm, lots of space), Linear (precise, keyboard-first) and TickTick (a familiar planner).
  - Adjectives: calm, precise, warm.
  - No glass, gradients or decorative blur.
  - One radius scale and one shadow level.
  - Motion only when state changes, and none under reduced motion.
  - Emoji only from user content: the 💡, 🔥 and 🏆 in `Tour.tsx` and `lib/celebrate.ts` become icons.
  - Celebrations stay, but shorter.
  - 44px minimum touch targets and one narrow breakpoint.
- **Accent:** already a palette (`color.ts:1`, 9 presets). Tighten `parseSettings` so any non-preset hex falls back to the default, and settle the final palette in the mocks (about 10 colours).
- **Implementation order on a branch:**
  1. `tokens.css` and `components/ui/` primitives (button, input, menu, dialog, chip, card, segmented control).
  2. App shell and navigation.
  3. Task row and drawer.
  4. View modes.
  5. Calendar.
  6. Habits and Focus.
  7. Progress.
  8. Settings.
  9. Popups (quick-add, reminder, mini window).

  Everything ships at once in v1.0.0.
- **Positioning (D180):** README and the first tour slide lead with "The planner you do with friends", with "Capture anything instantly, even offline" as the supporting line. Until v1.2 exists, the friends half is presented as "coming soon".

## 11. Rename (D185, D188)

- **Change everywhere:** the product name, the bundle identifier in `tauri.conf.json`, the deep-link scheme, the window titles, the installer, the README and the UI copy.
- **First launch:** when the new app-data folder has no database and `%APPDATA%\com.momentum.planner` (or the macOS/Linux equivalent) exists, copy `momentum.db` with its WAL sidecars, `attachments/` and `backups/` across before the database opens. This runs in Rust `setup`, next to the pre-migration backup. The old folder stays in place.
- **The updater** points at the renamed repository's releases. Testers install the renamed app once and uninstall the old one by hand.

## Edge cases

- **A user's default view was Logbook, Matrix, Countdown or Stats:** it's mapped as in §1, so they don't land on a blank page.
- **A list's layout was `kanban`** and the list loses all its sections: Board still works, with everything Unsectioned (D88).
- **A smart view saved in Board mode:** impossible. Board isn't offered there, and the parser falls back to List.
- **Countdown migration on a database with zero countdowns:** no rows, and the table is still dropped. Old JSON backups containing countdowns still import.
- **The background setting points at an image file:** the file is deleted with the folder, and the setting is ignored.
- **The mini window was open on the Matrix tab:** unchanged.
- **The Help registry is missing a command:** the test fails in CI.

## Verification

- **Domain tests:** the feature registry (coverage of every palette command and `GO` key; `done` keys are unique), the `layout` migration in `parseSettings`, the countdown-to-event conversion, voice mappings, and matrix scoping to a view's tasks.
- **Migration test:** a seeded v0.9.1 database with countdowns of every combination, every old layout value and a background set opens in v1.0 and all of them are converted.
- **Real app:**
  - Every view in every mode.
  - The bar at the top and at the bottom.
  - Narrow width.
  - Getting started ticks itself.
  - The tour runs on a fresh profile only.
  - Help search.
- **`npm run screenshots`,** with new What's new images in `public/whats-new/1.0.0/`.

## Acceptance

- The navigation has Inbox, Today, Upcoming, Calendar, Habits, Focus, Progress and lists. Nothing else is top-level.
- No data is lost from countdowns, layouts or saved views.
- Every command has help text.
- The approved mocks and the shipped screens match.
