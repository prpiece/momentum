# Spec: v1.2 Remove gamification, match versions, ready the phone app (Track A)

Decisions: D256, D257, D258, D267 (phone items), D268. Adds to [v1.2-mobile.md](v1.2-mobile.md), which still defines the phone app itself.

## Goal

v1.2.0 is the first release that ships the desktop and the phone together, with the same version number. It removes every reward mechanic, so Momentum reads as a calm planner, and it brings the phone app to a state that's ready for the stores.

## Out of scope

- Any change to the `Task` type (Track B owns it, D258).
- Supabase migrations or server functions (Track C).
- Store listings, store accounts and payments. Store-based phone updates are planned here but switched on at market launch.

## Remove gamification (D256)

- **Delete:**
  - `src/features/celebrate/` (overlay, Today streak, trophy shelf, trophy looks) and `src/lib/celebrate.ts`;
  - the share card: `src/features/progress/ShareDialog.tsx`, `drawShareCard.ts`, `src/domain/shareCard.ts` and their tests;
  - perfect days: `src/domain/perfect.ts` and its test, plus every caller.
- **Clean up the callers** that the deletion leaves dangling: `App.tsx`, `TaskCheckbox.tsx`, `CheckinButton.tsx`, `HabitDetail.tsx`, `TaskView.tsx`, `Tour.tsx`, `stores/progress.ts`, `stores/data.ts`, `stores/habits.ts`, `domain/stats.ts`, `domain/sync.ts`, `Logo.tsx`, `AppIcon.tsx`, `lib/os.ts`. Read each one before cutting; some only import an icon or a colour.
- **Settings:** remove the celebration and sound-on-complete settings that exist only for rewards. Stored keys that no longer exist are ignored when settings are read, and a settings test proves it.
- **Progress** keeps completions over time, focus time and the heatmap, and nothing else. No points, levels, ranks or "perfect" wording.
- **Habits** keep each habit's own current and best streak.
- **The feature registry, tour, Getting started and Help** lose every entry for removed features. `features.test.ts` must still pass.
- **Tokens:** retire `--streak` and the trophy metal colours `m-*` if nothing else uses them, then update `tokens.test.ts`.
- **The phone:** remove any trophy or streak wording from `mobile/` and the phone's What's new.
- **CHANGELOG:** one honest line saying rewards were removed and why.

## One version line (D257)

- A test (in `src/shared.test.ts` or beside it) reads the four version fields and fails when they differ.
- CLAUDE.md's Releases section names all four files.
- A sync test fails when the desktop schema has a synced column that the phone's row mapping ignores.

## Phone, ready for the stores

From the deferred R1 list in PLAN (D255) and D267:
- **Widgets and lock-screen quick add:** a Today widget (next 3 tasks plus an add button) on Android and iOS.
- **Full-screen alarms** for high-priority reminders on Android, using full-screen intents and asking for the permission the first time someone sets one. iOS uses time-sensitive notifications.
- **Calendar drag polish:** lift, haptics, and a live time label.
- **The "update required" server signal.**
- **Store-update prep:** version codes are generated from the shared version, and there's a checklist in `docs/specs/v1.1-launch-checklist.md` style for switching store updates on at launch.

## Verification

- `npm test` and `npm run build` pass; `npm run lint:selectors` is clean.
- A search of `src/` and `mobile/src/` for `trophy`, `perfect`, `celebrat`, `shareCard` and `TodayStreak` finds nothing (case-insensitive).
- Real-app check: complete a task and check in a habit on desktop and phone. Nothing celebrates, Progress shows only statistics, and each habit still shows its streak.
- `npm run screenshots` is regenerated and committed (D61).

## Acceptance

- There's no reward mechanic left anywhere in either app.
- All four version fields read 1.2.0, and the test enforces it.
- The phone app passes the v1.2-mobile acceptance list, plus widgets and alarms.
