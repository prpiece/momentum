# v1.2 store updates checklist

How the phone switches to Google Play and App Store updates at market launch (PLAN D257). Until then the phone is a local Android build or Expo Go, and nothing here is live. Store accounts, EAS and listings wait for the listing date (D259). Tick items off here as they're done.

## Already in place (v1.2.0)

- [x] **One version.** `mobile/app.json` carries the same version as the desktop, and `src/shared.test.ts` fails when the four version fields differ.
- [x] **Build numbers from the version.** `mobile/app.config.js` turns `1.2.3` into Android `versionCode` 10203 and iOS `buildNumber` "10203", so a release bumps only `version`. Minor and patch stay below 100.
- [x] **Update required.** Each sync reads `server_meta.min_client_schema`, so a phone that's too old shows "Update Momentum to keep syncing" even when it has nothing to push. On Android the banner's Update button opens the Play listing.

## You: accounts and listings

- [ ] **Google Play Console:** create the app with package `com.momentum.planner`, then run the closed test (12 testers for 14 days in a row) before production.
- [ ] **Apple Developer Program:** enrol, create the app with bundle ID `com.momentum.planner`, and note its numeric App Store ID.
- [ ] **EAS:** `npx eas-cli@latest init` in `mobile/`, then sign in to the Expo account that builds the store binaries.
- [ ] **Signing keys:** let EAS manage the Android upload key and the iOS certificates, or upload your own. Keep a copy of the Android upload key outside the repo.

## Claude: code at launch

- [ ] **App Store link:** set the iOS `STORE_URL` in `mobile/src/ui/Banner.tsx` to `https://apps.apple.com/app/id<App Store ID>`.
- [ ] **`eas.json`:** a `production` profile, plus `submit.production` with the Play track (`internal` first) and the App Store Connect app ID. Don't set `autoIncrement`, because build numbers come from the version.
- [ ] **Release workflow:** after the desktop draft release in `.github/workflows/release.yml`, run `eas build --platform all --profile production --non-interactive` and `eas submit` with an `EXPO_TOKEN` secret. Gate it on a repository variable so it stays off until launch.
- [ ] **What's new on the stores:** the Play and App Store release notes come from the same `## vX.Y.Z` section of `CHANGELOG.md`, which the phone already bundles.
- [ ] **Raising the floor:** when a release changes the sync protocol, bump `CLIENT_SCHEMA` in `src/lib/sync/engine.ts`, ship both apps, and raise `server_meta.min_client_schema` only after the stores have approved the phone build.

## Together: checks before switching on

- [ ] Install the Play internal-track build over a local build and check that the data is still there.
- [ ] Set `min_client_schema` above the installed build's schema on a test project, and check the banner and its Update link on both platforms.
- [ ] Ship a patch release through the whole path: tag, desktop draft, EAS build, store review, update on a phone.
