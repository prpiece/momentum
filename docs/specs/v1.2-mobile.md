# Spec: v1.2 iOS and Android

Phase B2. Decisions: D107 (ADR 0003), D200, D224–D228.

## Goal

Momentum runs on iPhone and Android phones as a Tauri 2 mobile build of the same React UI, `src/domain/`, SQLite store and sync engine. A user who signs in with the same email sees the same data on their phone and computer within seconds. The phone works fully offline, like the desktop app. It is published on the App Store and Google Play.

## Out of scope

- Tablets get the phone build as-is (it reflows); no tablet-specific layout.
- Home-screen widgets, Siri / Assistant shortcuts, Apple Watch / Wear OS.
- Push notifications from the server. Nothing in v1.2 needs them: reminders are local (below), and sync runs when the app is open.
- Background sync while the app is closed.
- Voice input (the Rust capture and the sherpa-onnx model are desktop-only).
- Sign in with Apple and Google (D228). Email code only, as on desktop.
- Friends, leaderboards and sharing (v1.3, v1.4). Payments (D190/D191).

## One codebase, gated by platform

- **Detection:** add `isMobile` (and `mobileOS: "ios" | "android" | null`) to `src/lib/platform.ts`, from `@tauri-apps/plugin-os` `platform()` or, without a new dependency, the user agent. **Bug to fix first:** `isMac` tests `/Mac/` on the user agent, and iPhone and iPad agents contain "Mac OS X", so iOS would get ⌘ labels and the macOS data path. `isMac` must exclude iOS.
- **Rust:** desktop-only plugins move to `[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]` in `Cargo.toml` and are registered under `#[cfg(desktop)]` in `lib.rs`: global-shortcut, autostart, single-instance, updater, process, window-state, and the `tray-icon` feature. Voice (`voice.rs`, `cpal`, `sherpa-onnx`, `reqwest`, `tar`, `bzip2`, `sha2`) is desktop-only too; its commands are not registered on mobile.
- **Capabilities:** `default.json` gains `"platforms": ["windows", "macOS", "linux"]`; a new `mobile.json` grants only what mobile uses: `core:default`, `sql:default`, `sql:allow-execute`, `notification:default`, `dialog:allow-open`, `dialog:allow-save`, the scoped `opener:allow-open-url`, and the `secret_*` commands. `popups.json` stays desktop-only.
- **Frontend:** everything behind `os.ts` that is desktop-only is skipped when `isMobile`: tray and close-to-tray, global shortcuts, the quick-add, reminder and mini windows, launch at login, the updater and `UpdatePrompt`, `WindowControls`, the Scale/zoom setting and Ctrl +/−. Settings hides their rows. The feature registry (`FEATURES`) gets a `desktopOnly` flag so Help, Getting started and the tour skip them; the palette stays (opened from Search).
- **Keyboard text:** no keycaps or "Ctrl K" hints on mobile. `<Keys>` renders nothing when `isMobile`.

## Layout and touch

The phone layout (D200) is the starting point; mobile always uses it, at any width.

- **Safe areas:** `viewport-fit=cover` in `index.html`; `PhoneBar`, sheets, toasts and the page head pad with `env(safe-area-inset-*)`. No content under the notch, the Dynamic Island or the Android gesture bar.
- **Keyboard:** quick add and the task sheet stay above the on-screen keyboard (`interactive-widget=resizes-content` on Android; on iOS, the `visualViewport` resize sets a `--kb` offset). Enter submits quick add; the input keeps focus for the next task.
- **Touch targets:** every control at least `--touch` (44px).
- **Hover-only paths need a touch path:** `Tip` tooltips (long-press or nothing; never the only way to learn something), the Focus picker's subtask flyout (tap the chevron), row hover actions (swipe or the drawer).
- **Swipes on task rows:** right completes, left opens a menu (Date, Priority, Delete). This is new UI; it uses the row's existing actions.
- **Drag and drop:** dnd-kit `PointerSensor` with `distance: 5` would steal scrolls. On touch, use `{ delay: 250, tolerance: 8 }` (press and hold), with a light haptic if `tauri-plugin-haptics` is added (optional).
- **Back:** Android's back gesture closes the top sheet, dialog or menu, then goes back in view history, then leaves the app. iOS: an edge swipe closes the task sheet.
- **Native selects:** WKWebView and Android WebView show their own pickers for `<select>`, `<input type="date">` and `type="time"`. Keep them (D206).
- **Dark mode** follows the system on first launch, as on desktop.

## Data, files and storage

- SQLite lives in the app's sandboxed data folder; migrations run on open, as on desktop. `dataDirLabel` shows nothing on mobile (the folder isn't reachable by the user).
- **Note images:** the asset protocol URL differs on Android (`http://asset.localhost`); go through `convertFileSrc` everywhere and check images render on both platforms. Picking an image uses the photo library (`dialog` open with an image filter); verify it returns a readable path on both.
- **Backgrounds (D222):** same as note images.
- **Export backup:** `dialog` save may not reach a user-visible folder on mobile. Verify on both; if it fails, export through the share sheet (iOS `UIActivityViewController`, Android `ACTION_SEND`), which needs a small plugin. Import uses `dialog` open.
- **Pre-migration backups** stay in the sandbox; the "restore a backup" flow reads them from there.

## Sign-in, tokens and sync

- Sign-in is the same email code screen. The code field uses `autocomplete="one-time-code"` and `inputmode="numeric"`, so iOS offers the code from Mail and Android from its keyboard.
- **Token storage:** `keyring` 4 is now only sample code; its API moved to `keyring-core` with a store crate per platform. Move `secrets.rs` to `keyring-core` with `apple-native-keyring-store` (macOS and iOS Keychain), `android-native-keyring-store` (Keystore-encrypted SharedPreferences) and the Windows and Linux stores. The three `secret_*` commands keep their names and their one-key limit. Desktop users keep their stored token: the store, service and account names must match what `keyring` 4 wrote, so check that with a signed-in desktop build before release.
- **Sync schedule on mobile:** the app is suspended in the background, so the 5-minute interval and the Realtime channel only run while it is in front. Add: sync on resume (`visibilitychange` to visible) and push the outbox on going to the background (best effort; the OS gives a few seconds). Writes still sync 2 s after the edit while open.
- **Device rows:** `platform` is `ios` or `android`. Fix the v1.1 bug first: the Account page shows "Device" when the platform update after the first sync doesn't run (seen on a v1.1.0 install); set the platform on every sign-in and on startup when it's missing.
- **Update required:** when `sync_push` answers `update_required`, mobile says "Update Momentum in the App Store / Google Play" with a store link, instead of the updater prompt.
- **Handle field (v1.1 bug, ship in v1.1.1 before v1.2):** strip a leading `@`, show a fixed `@` prefix, and say "Leave out the @" when it's typed mid-handle.

## Reminders and the focus timer

The desktop checks reminders every 30 s in JavaScript (`reminderScheduler.ts`) and shows its own window. A suspended phone app runs no timers, so mobile hands reminders to the OS.

- **Scheduling:** compute the next fires with the existing pure `remindersBetween` / `startsBetween` / `digestBetween` (`src/domain/reminders.ts`) for the next 7 days, keep the earliest 60 (iOS allows 64 pending), and schedule them with `tauri-plugin-notification`'s `schedule` (`Schedule.at`). Each notification's id comes from the reminder `key`, so rescheduling is idempotent: cancel all pending, schedule the new set.
- **When to reschedule:** on startup, on resume, after any write (debounced like sync), and after a pull applies changes. Changing a task on the desktop moves the phone's reminder the next time the phone opens; that's the accepted limit without server push.
- **Tapping a notification** opens the app on that task, event or habit (the notification's `extra` carries the `ReminderTarget`).
- **Actions:** Done and Snooze 10 min as notification actions (`registerActionTypes`), if the plugin delivers the action to a suspended app on both platforms; otherwise tap-to-open only, recorded in PLAN.
- **Permission:** ask when the user first turns on a reminder or the focus timer, not at launch. Android 13+ needs `POST_NOTIFICATIONS`; exact alarms need `SCHEDULE_EXACT_ALARM` (or `USE_EXACT_ALARM` for a planner app; check Play policy for which applies).
- **Focus timer:** the timer already runs from timestamps, so it is correct after a resume. Starting a phase schedules one local notification at its end; pausing, skipping or stopping cancels it.
- `reminder_log` keeps working as the "already fired" record; on mobile, an OS-delivered notification counts as fired when the app next opens.

## Stores and accounts

- **Account deletion is required by both stores** (App Store 5.1.1(v), Google Play's account-deletion policy), so the launch-checklist item "Delete account with a 7-day grace period" is a v1.2 blocker:
  - Settings → Account → Delete account, as in the v1.1 spec.
  - Google Play also needs a web page where people can ask for deletion without the app: add `site/delete-account.html` (steps plus the support email).
- **App Store:** Apple Developer Program (USD 99/year). Privacy nutrition label: email address, user content, identifiers (device ID), linked to the user, not used for tracking. No tracking, so no ATT prompt. Export compliance: HTTPS only, exempt.
- **Google Play:** a developer account (USD 25 once). A personal account created after 13 November 2023 must run a closed test with at least 12 testers opted in for 14 days in a row before it can apply for production. Plan about three weeks for this, and start it as soon as the first Android build installs. Data safety form: the same data as the App Store label; data encrypted in transit; deletion available.
- **Privacy policy:** add iOS and Android to the device platforms, Apple and Google as app distributors, and the delete-account page. Update the "Last updated" date.
- **Store listing:** name "Momentum" plus a subtitle (D192: run the USPTO/EUIPO search first); screenshots from the phone layout; age rating 4+ / Everyone; the Privacy and Terms URLs.

## Build and release

- **Android** builds on Windows: Android Studio, SDK, NDK and Java 17; `npm run tauri android init` creates `src-tauri/gen/android` (commit it). Release builds are AABs signed with an upload key (kept out of the repo, a CI secret), with Play App Signing. `versionCode` comes from the app version.
- **iOS** builds need macOS. Use a GitHub Actions macOS runner with `npm run tauri ios build --export-method app-store-connect`, signing through an App Store Connect API key (CI secrets), then upload to TestFlight. `src-tauri/gen/apple` is created by `tauri ios init` on that runner the first time and committed.
- **Workflow:** `.github/workflows/mobile.yml` on a `vX.Y.Z` tag. It builds the signed AAB and IPA and uploads them to the Play internal track and TestFlight. Publishing to production stays a manual step in each console (like the desktop draft release, D59).
- **Versions:** one version for all platforms. CHANGELOG feeds the store "What's new" text.
- **Actions minutes:** macOS runners count 10× on a private repo (D224). Estimate the iOS job's minutes before the repo goes private.

## Verification

- `npm test` and `npm run test:server` pass; new pure code (picking the next 60 fires, the mobile capability set) gets tests.
- Android emulator and a real Android phone; iOS Simulator and a real iPhone via TestFlight:
  - fresh install, use offline, then sign in (fresh and resume paths, D118);
  - a desktop edit shows on the open phone within seconds (Realtime), and a phone edit on the desktop;
  - edit offline on both, reconnect, fields merge;
  - a reminder fires with the app closed and tapping it opens the task; the focus timer's end notification fires while the app is in the background;
  - the keyboard never covers quick add; nothing sits under the notch or gesture bar;
  - back gesture, swipes and drag (press and hold) work, and scrolling never starts a drag;
  - export and import a backup; a note image shows;
  - delete account, then sign in during the grace period cancels it;
  - dark mode, the largest system font size, VoiceOver and TalkBack reach every control.
- Desktop regression: a signed-in v1.1 desktop keeps its session after updating (keychain names unchanged), and tray, hotkeys and the updater still work.

## Acceptance

- Momentum is live on the App Store and Google Play.
- A user can install it, use it offline, sign in with an email code and see their desktop data.
- Reminders and focus-timer alerts arrive while the app is closed.
- Account deletion works in the app and from the web page.
- Nothing desktop-only appears on a phone.
