# Spec: v1.2 iOS and Android (Expo companion)

Decisions: D224, D228, D229. ADR 0006 (supersedes 0003). Tickets: [v1.2-mobile-tickets.md](v1.2-mobile-tickets.md).

## Goal

Momentum on iPhone and Android is a native-feeling companion to the desktop app. It handles the things people do on a phone:
- capture a task in seconds;
- see today and the calendar;
- tick things off;
- check in a habit;
- run a focus timer;
- get reminded.

It works fully offline. With the same email signed in, the phone and the computer show the same data within seconds. It ships on the App Store and Google Play.

## Out of scope

- **Desktop-only views and features:**
  - Board, Matrix and Timeline views;
  - Progress (trophies, charts, the share card);
  - voice input, custom backgrounds, the mini window, the tray and global shortcuts;
  - the command palette, .ics import, and backup import/export (export comes later).
- **Phone extras for later:** widgets, Live Activities, Siri / Assistant shortcuts, watch apps, a tablet layout (tablets get the phone layout).
- **Server-side:** push from the server, and background sync while the app is closed.
- **Sign-in:** Sign in with Apple and Google (D228); email code only.
- **Later releases:** friends, leaderboards and sharing (v1.3, v1.4), and payments.

## What the phone app does

Proposed scope. Design ticket D1 confirms or trims it before any UI is built.

| Area | On the phone |
|---|---|
| Today, Inbox, Upcoming, lists | See, complete, reorder within a list, move between lists. Subtasks show under their parent (D196). |
| Quick add | The same natural-language tokens as desktop (`domain/quickAdd.ts`): dates, `!priority`, `#tag`, `~list`, `every …`. Chips show what was understood (D219). |
| Task details | Title, notes (Markdown shown as text; desktop note images show a placeholder, because attachments don't sync), due date and time, repeat, priority, list, tags, subtasks, reminders, delete. |
| Search | Fuzzy search over tasks (`domain/fuzzy.ts`). |
| Calendar | Day, 3-day and month views plus an agenda list. Events and scheduled tasks, all-day row, recurring occurrences (`domain/recurrence.ts`). Create by tapping a slot; move and resize by press-and-hold drag, snapping to 15 minutes. Create and edit events. |
| Habits | Today's habits, check-in (once, count and amount, limit, quit; D217), streaks, the past-year map. Create and edit habits. |
| Focus | Pomodoro and stopwatch on a task; an alert when a phase ends, even with the app closed. |
| Reminders | Local notifications for tasks, events, habits and the daily digest. |
| Account | Email-code sign-in, handle, devices, sign out, delete account. |
| Settings | Theme, accent, week start, time format, notifications, account, About (Terms, Privacy, version). |

**Data rule:** the phone stores every synced table, even ones it never shows (folders, sections, countdown fields, focus history, desktop-only settings). Edits travel as field patches, so the phone never overwrites or drops what it doesn't display.

## Architecture

- **Repository layout:**
  - `mobile/` is the Expo app, with its own `package.json` and the Expo Router app directory.
  - The shared code stays where it is (`src/domain`, `src/db`, `src/stores`, `src/lib/sync`).
  - Metro resolves it through `watchFolders` and a path alias; nothing is moved or copied.
- **Shared, as-is:** `src/domain/*`. It's pure TypeScript using date-fns, rrule, chrono-node and ical.js, with no DOM or Tauri imports. This includes `calendar.ts` (`viewDays`, `calendarItems`, `layoutDay`, `snap`, `droppedSchedule`, `resizedSchedule`), `quickAdd`, `recurrence`, `reminders`, `habits`, `focus`, `fuzzy`, `taskViews`, `settings` and `sync`.
- **Shared after a small refactor:**
  - **`src/db/client.ts`:** gets a pluggable driver (`select`, `execute`, `transact`), so the repos, stores and sync engine run on Tauri's SQL plugin on desktop and on `expo-sqlite` on the phone.
  - **UI side effects move out of the stores:** today the stores call toasts (`sonner`), `withTransition` and React hooks such as `derive` in `features/tasks/selectors.ts`. They become injected callbacks or move into a shared pure module.
  - Desktop behaviour must not change.
- **Database:**
  - the same SQL files (`src-tauri/migrations/*.sql`), applied in order on the phone and tracked with `PRAGMA user_version`;
  - the sync triggers (0009) come along unchanged;
  - `CLIENT_SCHEMA` is shared, so the server's `update_required` applies to both apps.
- **Sync:**
  - the same engine and Supabase project;
  - supabase-js, with the refresh token in `expo-secure-store` and the session in memory (as on desktop);
  - `AppState` starts and stops token refresh and triggers a sync on resume;
  - pending changes are pushed on going to the background (best effort);
  - Realtime runs while the app is open.
- **UI stack.** Climb the ponytail ladder for each piece and take a library only when its ticket shows it's needed:
  - **Navigation:** Expo Router, with a native stack and bottom tabs.
  - **Task details and quick add:** native sheets (the `formSheet` presentation).
  - **Gestures:** `react-native-gesture-handler` and Reanimated (they ship with Expo).
  - **Lists:** `FlatList`; FlashList only if a long-list test shows a need.
  - **Pickers:** native date and time pickers.
  - **Calendar:** drawn from `layoutDay`; no calendar library.
  - **Tokens:** generated from `src/styles/tokens.css` into a TS module by a script, and used through `StyleSheet`. No Tailwind or NativeWind unless the design system ticket shows a need.
  - **Fonts:** Inter, Bricolage Grotesque and JetBrains Mono through `expo-font`.
- **Notifications:** `expo-notifications` for scheduled local notifications, with Done and Snooze actions.
- **Builds:** EAS Build and EAS Submit (TestFlight and the Play internal track). The Android development build also runs locally on Windows. EAS Update is not used in v1.2.
- **Desktop:** nothing in `src-tauri/` changes.

## Reminders and focus alerts

A suspended phone app runs no timers, so the OS delivers them:
- **What gets scheduled:** the next 60 fires within 7 days, from the shared `remindersBetween` / `startsBetween` / `digestBetween` / `dedupeFires`. iOS allows 64 pending notifications.
- **Idempotent:** cancel all, then schedule the new set. Each notification id comes from the reminder `key`.
- **When to reschedule:** on start, on resume, after local writes (debounced) and after a pull.
- **Tapping** opens the task, event or habit. A deleted target shows a short "This was deleted" message.
- **Focus:** a phase end is one scheduled notification; pause, skip and stop cancel it.
- **Permission:** ask when the user first sets a reminder or starts a timer, not at launch. If it's denied, Settings says so and links to the system settings.
- **Android:** `POST_NOTIFICATIONS`. For exact timing, `SCHEDULE_EXACT_ALARM` or `USE_EXACT_ALARM`; decide from Play policy and record it in PLAN.
- **Accepted limit:** a change made on the desktop moves the phone's reminder the next time the phone opens.

## Platform behaviour

- iOS and Android each keep their own conventions where people expect them: back behaviour (Android back, iOS swipe-back), sheets, date pickers, the notification permission prompt, haptics.
- Everything else is one shared design built from Momentum's tokens.
- Safe areas come from `react-native-safe-area-context`. The keyboard never covers the field being typed in.
- Large system text, VoiceOver and TalkBack are supported from the start, not as an afterthought.

## Stores, accounts and legal

- **Account deletion is required by both stores,** so it is a v1.2 blocker:
  - in the app: Settings → Account → Delete account, with a 7-day grace period; signing in during it cancels the deletion;
  - on the web: `site/delete-account.html`;
  - on the server: a scheduled job, which also clears deleted items' content after 30 days (the Privacy policy's promise).
- **App Store:**
  - Apple Developer Program;
  - privacy label: email, user content, device ID, linked to the user, no tracking;
  - export compliance: HTTPS only.
- **Google Play:**
  - a personal account must run a closed test (12 testers, 14 days in a row) before production;
  - Data safety form;
  - the deletion page URL.
- **Privacy policy:** add iOS and Android, Apple and Google as distributors, Expo (EAS) as the build service, and the deletion page. **Terms:** drop "coming soon" for deletion.
- **Timing:** the store accounts open around 2026-11-25 (see the tickets).

## Verification

- **Tests:** `npm test` and `npm run test:server` pass. The shared code keeps its Vitest tests. New pure logic gets tests beside it.
- **Mobile tests:** a small set for the driver and migrations, run against `expo-sqlite` in a development build, or `node:sqlite` with the same SQL.
- **Devices:** the Android emulator, a real Android phone, and a real iPhone through TestFlight:
  - fresh install, offline use, then sign in (fresh and resume, D118);
  - a desktop edit appears on the open phone within seconds, and the other way round;
  - offline edits on both merge by field;
  - fields the phone doesn't show survive a phone edit (edit a task's title on the phone; its section and Matrix quadrant stay on desktop);
  - reminders and focus alerts arrive with the app closed, and tapping opens the right place;
  - calendar: drag to move and resize, a recurring event's occurrence, all-day items, week start, 12/24 h;
  - the keyboard never covers quick add; nothing sits under the notch or the gesture bar;
  - delete account, then cancel it by signing in during the grace period;
  - dark mode, the largest text size, VoiceOver and TalkBack.
- **Desktop regression:** the driver refactor leaves desktop behaviour unchanged: tests, screenshots and a signed-in sync round trip.

## Acceptance

- Momentum is live on both stores.
- A new user can use it offline, sign in with an email code, and see and edit their desktop tasks, calendar and habits.
- Reminders arrive with the app closed.
- Account deletion works in the app and on the web.

See the tickets. The design gates run first, alongside the shared-core refactor, then the screens one area at a time. Google's closed test sets the release date.
