# Spec: v1.2.1 Fixes

A review of v1.2.0 found 2 critical, 16 high, 23 medium and 4 low issues, and testing found more. This release fixes all of them. Every fix starts with a failing test that reproduces the bug (or a written reason why a test isn't possible), and every finding is checked against the code first: a finding that turns out to be wrong is recorded as "not a bug" with the reason, never patched blindly.

Decisions: D287 (agent deletes and Trash), D288 (one command set for every connection), D289 (server version check).

## Work groups

The groups touch different files, so they run in parallel and merge in this order.

### G1 Agent, MCP, CLI, Windows PATH (`src-tauri/src/agent.rs`, `src/lib/agentApi.ts`, `src/domain/agentOps.ts`, `cli/`)

- **C1 PATH wipe** (`agent.rs` `windows_path`): match the value name case-insensitively (`Path`, `PATH`, `path`), and abort without writing if `reg query` fails or the value can't be read. Never write a PATH shorter than the one read.
- **Delete and restore for agents (D287):**
  - `delete_task` moves one task to the Trash and returns the full task it removed.
  - `restore_task` brings a trashed task back.
  - Delete needs the full id: short prefixes still work for reads, but a delete with a prefix fails.
  - A task with subtasks can only be deleted with `withSubtasks: true`, and the response lists every subtask removed.
  - No bulk delete.
  - CLI: `momentum delete <full-id> [--with-subtasks]`, `momentum restore <id>`, `momentum trash` (list). MCP tools: `delete_task`, `restore_task`, `list_trash`.
- **H5** `add`: the response includes newly created tags (read the tags after `createFromText`).
- **H7** `complete` on the last occurrence of a recurring task returns the completed occurrence instead of throwing.
- **H8** `update` on a recurring task goes through `editOccurrence` (this occurrence by default; `scope: "following" | "all"` optional).
- **Medium:**
  - `tags: ["#"]` is refused, and `"work"` / `"Work"` resolve to one tag;
  - `add` respects `MAX_SUBTASK_DEPTH`;
  - `habits` reports weekly totals for weekly habits;
  - a bad `deadline` error names the deadline field.
- **Low:** the Windows CLI self-update copy falls back to copy-to-temp-and-rename when `momentum.exe` is locked by a running MCP client, and reports it instead of failing.

### G2 Parser, calendar, domain rules (`src/domain/quickAdd.ts`, `calendar.ts`, `taskViews.ts`, `habits.ts`)

- **H3** `5pm 30m` gives a 30-minute timed task: a duration token sets the end when there's a start and no `until`.
- **H4** `15 min`, `15 mins`, `1h 30m`, `1 h 30 min`, `90 minutes` are durations and never reach the date parser.
- **Tag after priority:** `!high #tag` and `#tag !high` both keep the tag. Test every token order.
- **H6** `layoutDay` groups overlaps by real start and end times; the drawn minimum height only affects drawing. Back-to-back 15-minute and 45-minute tasks stack.
- **Medium:**
  - the DST fall-back lookback in `calendarItems` uses wall-clock days, not 86400 s;
  - `inSmartScope("today")` and `completedPerDay` respect `dayEndHour`;
  - `weekDoneCount` counts only days that have passed, from the habit's start date, for weekly limit and quit habits.

### G3 Server: security, consistency, bot parity (`supabase/`)

- **C2** `push_shared`: a create-shaped patch is refused when `(owner, tbl, id)` already exists, whether or not the patch has an `id` field. An editor can never write into an owner's private row. Add an RLS test that tries exactly this attack.
- **Medium:**
  - `set_member_role` never activates a pending invite;
  - `pass_on_shares` handles nested shares and writes `sync_gone`;
  - `purge_deleted` keeps `list_id` / `folder_id` for share tombstones and skips bad `deleted_at` values;
  - `server_write` and `insert_inbox_task` go through the same shared-write checks and advisory lock as `push_shared`;
  - `transfer_share` revokes or re-owns the old owner's invite links.
- **Bot parity (D288):** chats and the webhook can do everything the CLI does: add, list, view, search, update (date, deadline, duration, priority, list, tags), complete and reopen, delete to Trash, restore, habits, focus status, send. The rules match G1: full id or a number from the last listing; no bulk delete; subtasks need an explicit "with subtasks".
  - Each connection has a permission level: add-only, or full. The webhook is add-only by default.
  - The webhook takes `{ "command": "…" }` as well as `{ "text": "…" }`.
- **Server version (D289):** add `server_meta.schema_version` (bumped by every migration from now on) for the app to compare.

### G4 Stores, sync, Trash, desktop UI (`src/stores/`, `src/lib/sync/`, `src/db/`, `src/features/`, `src/lib/backup.ts`, `src/lib/shortcuts.ts`)

- **Trash (D287):**
  - Deleted tasks stay for 30 days instead of being purged on the next launch.
  - A Trash smart list shows them with Restore and Delete forever.
  - Restoring a subtask whose parent is trashed restores the parent too.
- **H9** `restoreBackup` keeps the restored settings: no debounced save of defaults after the settings row is replaced.
- **H10** Moving a recurring task to Someday clears or keeps its recurrence consistently for `following` and `all`, and treats `someday` like `none`.
- **H11** Desktop view-only shares block every edit path, not just quick add: checkboxes, drawer, context menu, board and Matrix drags, `ListDialog`, keyboard shortcuts. Use one `canEdit(listId)` selector.
- **H12** Shortcuts and Ctrl/Cmd+Z do nothing while any dialog is open. Track open dialogs centrally in `Dialog` so every dialog counts.
- **H13** `planApply` merges personal-layer patches onto the row instead of keeping only the highest version.
- **H14** An expired-JWT error refreshes the session. It never signs out, and never deletes the refresh token. Signing out is only for a refresh that's truly refused.
- **H15** The first sign-in on a second device pulls before pushing. A fresh device never pushes a default Inbox or default settings over the server's.
- **Server version (D289):** the app reads `server_meta.schema_version`. When the server is behind, it shows one clear message: "Sharing and connections need a server update", and disables those features. No generic "Something went wrong" toasts. Every server error toast says what failed.
- **Medium and low:**
  - stores:
    - removing a subscription mid-refresh doesn't bring its events back;
    - the reminder window's stale closure is fixed;
    - cycle guards in `descendants` and `depthOf`;
    - `updateTask` doesn't clobber `parentId` after `setParent`;
  - UI:
    - the `Dialog` focus trap skips disabled buttons;
    - Shift-click with a missing anchor selects from the clicked row;
    - a double click on a checkbox toggles once;
    - `HabitDetail`'s month grid stops at the last day of the month;
    - selecting text in the habit note popover doesn't start a drag;
    - disabled notification and sound controls aren't focusable;
    - Progress never shows "0h 60m";
    - `TimeGrid` and `Blocks` clean up on `pointercancel`.

### G5 Phone (`mobile/`)

- **H16** Habit colours are stored as the palette's hex values, and `parseHabit` accepts the `var(--h-*)` forms already stored and maps them to hex.
- **H17** View-only shares block taps, swipes, subtask rings, list moves, calendar drag and quick add, using the same shared `canEdit` rule as G4. G5 adds a local copy if G4 hasn't merged, then switches to the shared one.
- **H18** Quick add doesn't open a second modal over a sheet on iOS: close the sheet first, or render pickers inside the same sheet.
- **Medium:**
  - setting a repeat on a Someday task asks for a date first, instead of silently dropping the repeat;
  - focus notifications respect `notify.enabled` and `notify.focus`;
  - Today, Habits, Calendar and the widgets refresh on a `dayEndHour` change and when the day rolls over with the app open.

## Not in this release

- **Deploying the server.** Applying the November 14 migrations and these fixes to the live Supabase project, and deploying `inbound`. Both change the live server, so they wait for the owner's go-ahead (see `docs/connections-setup.md`).
- **A `createdBy: "agent"` marker on tasks.** Skipped for now. Trash already makes agent mistakes recoverable.
