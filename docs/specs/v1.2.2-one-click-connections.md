# Spec: v1.2.2 One-click connections

Decision: D290. Builds on D265 and D288 and ADR 0008. Status: planned, not built.

## Goal

Linking a chat takes one click and one approval instead of three steps. Today a user has to find an install link, get a 6-digit code in Settings → Connections, and type `/task link 123456`. After this change they click **Connect Discord** (or Slack, or Telegram), approve once in their browser or Telegram, and the app shows "Linked to @name on Discord" a moment later. The 6-digit code stays as a fallback.

## Out of scope

- Owner setup: creating the platform apps, the secrets, registering `/task`. That's done once by the project owner (`docs/connections-setup.md`). Users never see it.
- New bot commands, and changes to how commands run.

## How it works

One mechanism for all three platforms: the app asks the server for a **connect token**, and the platform's own install flow carries that token back to the `inbound` function. The function links the chat to whichever account owns the token. Nobody types anything.

### Connect token (server)

- **New RPC `create_connect_token()`** (authenticated) returns a 32-character random token (URL-safe: letters, digits, `-`, `_`). It's stored in `link_codes` with a 10-minute expiry and the caller's account. Reusing `link_codes` means `link_chat` and the expiry cleanup work unchanged.
- **The token can be used once.** `link_chat` already deletes the code it consumes.
- **Why a long token, not the 6-digit code:** it travels through URLs and third-party redirects, so it must not be guessable. The 6-digit code is only safe because it's typed by hand within 10 minutes.
- **A new migration** bumps `schema_version` to 3 (D289). The app's required version stays at 1, so older apps keep working; the new buttons check for version 3 and fall back to the code flow on an older server.

### Telegram (small)

- **Button:** opens `https://t.me/<bot username>?start=<token>`. Telegram allows up to 64 characters, so a 32-character token fits.
- **The user taps Start.** Telegram sends `/start <token>` to the bot.
- **Bot:** `/start <token>` is treated as `link <token>`. A plain `/start` without a token replies with the help text, as today.

### Slack (small)

- **Button:** opens Slack's install page, `https://slack.com/oauth/v2/authorize`, with the existing client id and scopes, `redirect_uri=<base>/slack/oauth`, and `state=<token>`.
- **The user approves the install.** Slack redirects to `slackOAuth`.
- **`slackOAuth`:**
  - stores the workspace's bot token as today;
  - if `state` is present, calls `link_chat(state, 'slack', '<team>:<authed_user.id>', ...)`. That's the same chat identity the slash command uses, so commands work at once.
  - The page then says "Linked. Go back to Momentum."

### Discord (medium)

- **Button:** opens `https://discord.com/oauth2/authorize` with:
  - `client_id=<DISCORD_APP_ID>`, `response_type=code`, `scope=identify applications.commands`;
  - `integration_type=1` (install to the user's account, so `/task` works in every chat);
  - `redirect_uri=<base>/discord/oauth`, `state=<token>`.
- **The user clicks Authorize.** Discord installs the app to their account and redirects to the new `/discord/oauth` route.
- **`/discord/oauth`:**
  1. exchanges `code` at `https://discord.com/api/oauth2/token` using `DISCORD_CLIENT_SECRET`, a new secret;
  2. reads the user with `GET https://discord.com/api/users/@me`;
  3. calls `link_chat(state, 'discord', <user.id>, <username>, {user_id})`, the identity the `/task` command already uses;
  4. shows "Linked. Go back to Momentum."
- **Discord's access token is thrown away** after reading the user id. Nothing is stored.
- **Owner setup (once):** copy the **Client Secret** from Developer Portal → OAuth2 into `DISCORD_CLIENT_SECRET`, and add `<base>/discord/oauth` under **OAuth2 → Redirects**.

### Shared rules for both redirect routes

- **Bad requests:** a missing or expired `state`, or a refused or failed exchange, shows a plain page: "That link expired. Start again from Momentum". It never shows a stack trace or any token.
- **Requests the platform didn't send:** an unknown `state` can't link anything, because the token is single-use, random and expires after 10 minutes. The code exchange only works with Discord's or Slack's real code for our app.
- **Rate limit:** the existing `hit_rate` key per IP-less route, `oauth:<platform>`, at 60 an hour.

### App (desktop and phone, D257)

- **Settings → Connections** (`src/features/settings/ConnectionsSection.tsx`, `mobile/src/app/connections.tsx`):
  - **Connect Discord / Add to Slack / Open in Telegram** buttons, each shown only when that platform is configured. The function reports which platforms have their secrets set through a new `GET <base>/platforms` (no secrets returned).
  - Clicking a button gets a connect token, opens the URL in the system browser (or the Telegram app), and shows "Waiting for Discord…".
  - The app then checks `my_connections()` every 2 seconds for up to 2 minutes, or until the new link appears. On success it shows "Linked to @name on Discord"; after 2 minutes, "Didn't hear back. Try again, or use a code."
- **The code fallback stays,** with a **Copy** button that copies the whole command (`/task link 123456`, `/momentum link …` or `link …`), not just the number.
- **Webhook:**
  - a **Copy URL** button;
  - two ready-made examples under it: an iPhone Shortcut ("Get contents of URL", POST `{"text": …}`) and a Zapier or IFTTT webhook step.
- **The desktop link opener's allow-list** (`src-tauri/capabilities/default.json`) gains `https://discord.com/oauth2/*`, `https://slack.com/oauth/*` and `https://t.me/*`. Nothing else is added.

## Owner checklist (done once, in `docs/connections-setup.md`)

1. **Discord:** add the **Client Secret** to the function secrets as `DISCORD_CLIENT_SECRET`, and add the redirect `<base>/discord/oauth`.
2. **Slack:** the redirect `<base>/slack/oauth` already exists. Nothing new.
3. **Telegram:** add `TELEGRAM_BOT_USERNAME` (the bot's @name, without the @) so the app can build the `t.me` link.

## Verification

- **Server tests** (`supabase/tests/`):
  - a connect token is 32 URL-safe characters, single-use, and expires after 10 minutes;
  - Telegram `/start <token>` links, and plain `/start` replies with help;
  - `slackOAuth` with `state` links `<team>:<user>`;
  - `/discord/oauth` with a faked token exchange links the user id;
  - bad, expired or reused `state` shows the expired page and links nothing;
  - `/platforms` never returns a secret.
- **App tests:** the polling stops on success and after 2 minutes, and the copy button copies the full command.
- **Real check:** connect Discord, Slack and Telegram on a fresh account with one click each, and `/task today` works straight after.

## Effort

- Telegram and Slack: about half a day together.
- Discord: about a day, most of it the OAuth route and its tests.
- App buttons, polling and copy: about half a day on each app.
