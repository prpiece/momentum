# AI agents change data through the running app, not the database file

The `momentum` CLI and the stdio MCP server send every read and write to a localhost API served by the desktop app's main window. They authenticate with a token from a file in the app data folder, and if the app is closed, the CLI starts it in the tray first. They never open `momentum.db`. Only the main window may write (D33): its Zustand stores are the in-memory source of truth, every write must go through the `db/` repos so sync triggers record it and the boundary validation runs, and a second process writing to SQLite would leave the UI stale and could race the sync queue. We rejected direct SQLite access (fast, and works without the app running, but it bypasses validation and sync) and a cloud API via Supabase (works for remote agents like ChatGPT, but needs an account and fails offline). A remote MCP endpoint can come later as an addition.
